1. 요약

기업 공시의 수치와 원문을 함께 검토하도록 지원한다. 서비스의 출력은 담당자의 내부 자료 확인과 최종 판단을 보조한다.

한 줄 정의 | 기업금융·여신심사 담당자가 공시 재무, 주석·상환위험 징후와 재무 패턴을 한 흐름으로 확인하고 추가 검토 사항을 정리하는 웹 서비스.

문제 | 재무 수치, 현금흐름, 주석, 뉴스가 분산돼 있어 정보 탐색과 검토 메모 작성이 번거롭다. 수치 변동만으로 사업상 원인을 확정하기 어렵다.

해결 방식 | 기업·연도 선택 → 핵심 재무와 회계 변동 → 업종별 징후·원문 → 비지도 패턴 → 뉴스·체크·메모. 계산값과 원문, 자료 상태를 함께 제시한다.

핵심 데이터 | OpenDART 기업·공시·재무제표·원본 문서, LoanSight 정제 DB, 업종별 비교 분포, 한국은행 참고 통계, 기사 원문 링크.

성공 기준 | 검토 정보 탐색 시간과 근거 추적 가능성을 평가한다. 업무 효과의 기준선·목표치·실측 결과는 미정이며, 기능 제공과 효과 달성을 구분한다.

2. 문제 정의

문제 정의는 기획안 v3.0에 기록된 현직자 인터뷰 취지를 따른다. 수치화되지 않은 업무 효과와 지역 효과는 미측정으로 둔다.

대상 (누가) | 은행 기업금융·여신심사 담당 행원. 상장사 공시를 이용해 기업대출 검토 자료를 준비하는 사용자.

상황 (언제·무슨 업무) | 연간 사업보고서 검토, 실적 변화 확인, 상환재원·유동성·우발부담과 담당자 추가 확인 항목 정리.

현재 방식 (As-Is) | DART에서 재무·감사·주석을 각각 탐색하고, 수치를 대조한 뒤 뉴스를 별도 검색하여 내부 양식에 옮긴다. 기획안에 기록된 인터뷰 취지에 따른 업무 흐름.

불편 · 손실 | 영업이익·감가상각·현금흐름 조회와 시각화, 심사 항목 작성이 번거롭고 뉴스 탐색 시간이 부족하다. 소요 시간·비용의 실측치는 미확인.

근거 · 출처 | 기획안 v3.0 「현업 문제와 서비스 목적」의 현직자 인터뷰 요약. 인터뷰 원본 공개 링크는 미확인. 공식 공시 원천: https://dart.fss.or.kr/

관련된 기존 서비스 | DART는 기업 공시 원문 조회를 제공한다. LoanSight AI는 원문을 대체하지 않고, 재무 변동·업종 비교·원문 근거·추가 확인을 연결해 검토 흐름을 보완한다.

지역 문제 ↔ 금융의 역할 | 특정 지역 문제를 검증한 자료는 없다. 기업금융 담당자의 공시 탐색 부담을 줄이고 상환능력 저하 징후를 확인하도록 지원한다. 지역 효과를 달성했다고 주장하지 않는다.

3. 목표와 성공 지표

핵심 목표는 정보 탐색 효율과 근거 추적 가능성이다. 목표치·기준선은 아직 합의된 값이 없어 미정으로 둔다.

목표 | 지표 | 현재 (기준선) | 목표치 | 측정 방법

검토 정보 탐색 효율 | 핵심 수치·원문·확인 항목을 찾는 시간 | 미측정 | 미정 / 담당: 오준탁·최수인 | 동일 기업·업무 조건의 도입 전/후 소요 시간 비교. 표본·절차는 별도 팀 검증 계획에서 관리.

근거 있는 검토 지원 | 요약 사실의 근거 추적률 / 수치·단위·방향 불일치 | 전체 범위 실측 미완료 | 미정 / 담당: 김동민·최수인 | 계산 결과와 원문을 대조하고 자료 없음·실패·부재 구분을 확인. 연체 예측력 지표로 대체하지 않음.

이번에 하지 않을 것: 임대업 주석 추출·요약, 은행 내부 자료 수집·전송, 여신 승인·거절/등급 자동화. 연체확률 예측·PDF·업종/지점 확대는 향후 검토.

4. 사용자와 시나리오

핵심 사용자는 은행 기업금융·여신심사 담당 행원이다. 서비스는 공식 공시로 확인 가능한 범위만 제공한다.

핵심 사용자 | 기업금융·여신심사 담당 행원. 기업 검토 시 사용하며 정확한 사용 빈도는 미정.

목표 · 불편 | 공시 재무의 변화와 주석 근거를 빠르게 확인하고 내부 자료로 더 확인할 질문을 정리한다. 분산 조회·복사·판단 근거 정리에 시간이 든다.

사용 시나리오 | 기업 검색 → 대상 업종·2025/OFS 확인 → 핵심 재무·영업CF → 변동 분해 → 주석/징후 원문 → 패턴·뉴스 → 체크와 메모 수정·복사.

최종 의사결정자 | 담당자가 은행 내부 거래·담보·상환약정 자료를 함께 검토한다. 여신 승인·거절과 내부 등급은 은행 담당 절차에 따른다.

사용자가 얻는 가치 | 재무 수치와 원문 근거를 왕복 확인하고 미확인 항목을 관리한다. 시간 절감·오류 감소는 기대효과이며 수치적 달성 여부는 미측정.

5.3 데이터·AI 활용 설계

주석과 절대 주의 조건은 비지도 모델 입력과 분리한다. 구조적 계산 불가 값은 대치하지 않으며 일반 결측 최대 1개만 학습집단 중앙값으로 대치한다.

활용 방식 | 규칙 기반 재무 계산·지표별 징후, 비지도 학습(Isolation Forest·K-means), 공시 주석 추출·LLM 요약.

필요한 이유 | 계산·절대조건은 코드로 재현하고, 다변량 패턴은 같은 연도·업종 집단에서 탐색한다. LLM은 확보한 공시를 읽기 쉬운 근거 요약으로 만든다.

입력 → 출력 예시 | OFS 선정 지표 → 집단 내 이상도·군집. 주석 원문 → 확인 사실/원문 근거/해석과 한계/추가 확인. 숫자·비율은 코드 계산.

평가 방법 | 원금액·산식·방향·추출 상태 대조, 고정 모델 재현성·군집 안정성·근거 연결 확인. 연체 정답 자료가 없으므로 연체 예측 정확도를 보고하지 않는다.

틀렸을 때 대응 | 구조적 계산 불가는 대치하지 않고 보류. 근거·단위·회계 범위가 불분명한 요약은 검수 대기. 신규 생성 실패와 저장된 결과·규칙 미리보기를 구분.

사용자에게 보여줄 근거 | 연도·OFS·사용 지표·관측/대치 수·비교기업 수·모델 버전·군집 중앙값·원문 접수번호와 표/문단 위치·검수 전 표시.

6.2 테이블 설계 (ERD)

아래는 최신 문서에서 필요한 데이터의 논리 구조다. 실제 배포 DB의 테이블명·제약·인덱스·접근 권한이 확인된 물리 ERD로 오해하지 않도록 구분한다.

논리 엔터티 | 한 행의 의미 | 논리 키 · 주요 관계 | 구분

기업 | DART 기업 1개 | 기업 식별키. 종목코드·DART 고유번호 매핑. 기업1:N보고서. | 기준

보고서 | 기업의 공시 문서 1개 | 접수번호. FK기업. 기준일·OFS·정정 버전. | 원천

재무 원금액 | 보고서의 계정 원금액 1개 | 접수번호+계정+기간+단위. FK보고서. | 원천/정제

주석 근거 | 표/문단에서 추출한 항목 1개 | 접수번호+위치+항목 식별키. 유형·방향·시점·금액·상태. | 원천/정제

패턴 결과 | 연도·업종·조합·모델 버전별 기업 결과 | 기업+연도+조합+모델 버전. 지표 입력과 연결. | 분석

체크·메모 | 기업 검토 항목/메모 1개 | 기업+연도+사용자/항목(저장 정책 미정). 근거 연결. | 업무

업무 도메인 구분 | 기업·보고서 / 재무·주석 원천 / 지표·징후·모델 결과 / 담당자 검토 기록. 위 표는 PRD의 논리 설계이며 기존 DB 물리 테이블·PK 확정을 뜻하지 않는다.

ERD 링크 · DB 선택 | 기준 관계: 기업1:N보고서1:N재무/주석, 지표·모델 결과는 기업·연도·버전으로 연결. 실제 ERD 링크·물리 FK는 김동민 확인 필요. 웹 정제 DB/대화 저장에 SQLite를 사용하나 전체 배포 스키마는 미확인.

6.4 품질 점검과 한계

키·관계: 기업 식별 매핑, 접수번호/계정/기간 중복과 정정 버전, 1:N 결합의 합계 중복을 확인한다.

수치·기간: 통화·단위·OFS·당기/전기·누적/당분기·잔액 정의를 맞추고 자산=부채+자본, 합계·부호·잔차를 검사한다.

상태: 결측과0, 무차입과미확인, 분모비양수·추출실패·공시상없음·검수대기·미평가를 분리한다.

주석: 제공/수취·원고/피고·당기/전기·한도/잔액, 표/본문 중복·부정문·교차참조를 확인한다.

패턴: 5지표 경로는 실제 관측4개 이상·일반 결측최대1개, 그 외 실제 관측3개 등록 조합은 참고. 비교기업30개 미만은 보류한다.

군집: 최소10개·실루엣0.25 이상과 안정성 기준을 확인한다. 미충족 시 군집 표시만 보류하고 사유를 남긴다.

판정: 자료·적용→절대→상대 순서, 반올림 전 경계 비교. 우선/보조/조건부는 검토 용도이며 가중치·위험등급이 아니다.

이 데이터로 알 수 있는 것 | 공시상 재무 수치의 변화, 업종 내 상대 위치, 명시된 주석과 확인 필요 사항, 동종 집단의 재무 패턴.

알 수 없는 것 · 화면 고지 | 은행 내부 연체·거래·담보 실사·미공개 상환약정과 실제 연체확률은 알 수 없다. “공시 기반 확인 지원이며 여신 승인·거절, 자산건전성 분류, 내부 등급 산정을 대신하지 않습니다.”
