### 작성 기준

요구사항 정의서 v0.0.4와 기획안 v2.0을 반영한 검토 전 초안이다. 이번 변경은 상환·연체 위험 사건 예측, 업종별 징후 패널, 주석 자동 추출 기준이다. 수용 여부는 검토 대기, 구현 가능 여부는 확인 필요이며 문서 작성이 개발·데이터 수집·모델 검증 완료를 뜻하지 않는다.

### 문서별 역할

PRD는 전체 목표와 범위, 요구사항 정의서는 필요한 결과와 수용 조건, 기능명세서는 입력·처리·출력·예외, WBS는 작업·담당·기간을 관리한다. WBS는 이번 요청에서 개정하지 않는다.

N은 LoanSight AI, R은 요구사항, F는 기능, S는 화면, U는 미정 질문이다. 요구 43개·기능 41개·화면 8개·미정 20개를 연결한다. 기존 N-F01~35를 유지하고 N-F36~41을 추가한다.

## 1 요약

LoanSight AI는 기업금융·여신심사 담당자가 영업이익·현금흐름·상환능력과 공시 주석을 함께 검토하도록 돕는다. 수치 변동, 업종별 확인 순서, 원문 근거를 연결하고 재무·주석을 결합한 향후 12개월 상환·연체 위험 사건 발생 확률을 개발한다. 제조·건설·도소매·부동산 임대 4개 업종을 대상으로 한다.

## 2 문제 정의

기획안의 현직자 인터뷰에는 영업이익 우선 확인, 감가상각·현금흐름 탐색과 화면 시각화·심사 항목 작성의 불편, 뉴스 탐색 시간 부족이 기록돼 있다. 원기록을 이번 문서 작업에서 독립 검증하지 않았다. 수치·주석 탐색과 검토 기록 초안을 한 흐름으로 연결해 누락을 줄이는 것을 목표로 한다.

감가상각은 임대업 인터뷰에서 출발한 항목이다. 모든 업종의 최우선 지표로 고정하지 않는다. 회계상 금액 변동 분해와 사업상 원인 설명도 구분한다.

## 4 사용자와 범위

주 사용자는 은행 기업금융·여신심사 담당 행원이다. 상장사(코넥스 포함)를 우선한다. 부동산·임대는 부동산 임대로 한정하고 장비·물품 렌탈, 운수·창고, 금융·보험, 지주회사, 스팩, 부동산 관리·중개는 제외한다. 세부분류 수준·기업·기간·복합 판정 비중·수동 변경 권한은 미정이다.

기업·기간·회계 범위·결산월과 적용 업종을 확인한다. 재무·변동·업종 비교, 주석과 징후 패널, 위험 사건 예측 근거를 검토하고 미확인 항목을 체크한다. 업종 수동 변경은 사유·근거를 남겨 재분석하며, 메모를 수정·복사한다.

### 6.2 원문과 논리 데이터 구조

보고서는 I.1 신용등급, II 사업, III 주석, IV.4 유동성·조달, IV.5 부외거래, V.1 외부감사, XI.2~4 우발부채·제재·후속사건 목차 단위로 저장한다. 업종/매핑 → 보고서/정정/시점 → 계정/산식 → 주석/검수 → 사건/라벨/특징/모델 → 결과/규칙/체크/메모를 연결한다. 물리 ERD·키·보존 정책은 미정이다.

### 6.3 수치 분석과 예외

영업이익 증감 분해는 매출 증감 - 매출원가 증감 - 판관비 증감이다. 실제 OP 증감과의 차이는 기타·조정으로 남긴다. 가상 검수 예: +100 -60 -10 = +30, 실제 OP +35이면 잔차 +5다. 이는 사업상 인과관계의 증명이 아니다.

OP/OCF와 채권·재고·매입채무·상각, 건설 계약자산을 함께 본다. 0/음수 분모·적자 전환·매출원가 미공시·기타수익 임대료는 불가/불완전 사유를 표시한다. 자사 3개년과 동종 중앙값/분포를 비교하며 세부분류 부족 → 상위 분류 → 비교 보류로 처리한다.

## 6.4 예측 대상과 사건 라벨

목표는 기준 공시일 이후 12개월 내 N-R17의 공시 기반 상환·연체 위험 사건이 발생할 확률이다. 실제 은행 대출 연체만의 확률이나 기존의 부도 단일 사건 확률로 해석하지 않는다. 규칙 기반 현재 징후 단계와도 별도 결과다.

| 라벨 사건 | 원문 대조 |
| --- | --- |
| 원리금 연체와 기한이익상실 | 실제 사건 발생과 조건 조항의 존재를 구분 |
| 어음 수표 지급거절 | 최초 발생일·공시일·금액·접수번호 |
| 회생 또는 채권은행 관리절차 개시신청 | 신청 사건의 최초일·유형·심각도 |
| 감사의견 비적정과 계속기업 불확실성 기재 | 당기 의견/기재의 알려진 시점·최초 사건일. 유형별 심각도 미정 |

상환·연체 관련이 확인되지 않은 관리종목 지정·상장폐지는 라벨에 넣지 않는다. API 미조회는 비발생의 증거가 아니다. 전체 12개월 관찰이 확인된 표본만 비발생으로 사용하고 관측 종료·추적 중단은 별도 처리한다.

### 6.5 후보 특징과 학습

재무 특징에 검증된 소송/제공 보증/담보, PF 만기구간·조건부 의무, 1년 내 만기 차입 비중, 리스부채, 기한이익상실 조항, 감사의견·등급 변화를 후보로 결합한다. 후보/채택을 구분하고 낮은 확보율 변수·뉴스·LLM 임의 확률은 제외한다. 최종 특징·결합 모델·목표치·보정·표시/보류는 미정이다.

검증된 항목만 요약/모델에 공통 사용한다. 기준일 이후의 후속사건·정정은 과거 특징으로 역유입하지 않는다. 참조문 미해결·원문 미확보·파싱 실패도 구분해 기록한다.

### 시스템과 운영

기획안은 기존 시연 기반을 Python 3 표준 라이브러리 서버, HTML·CSS·JavaScript·SVG 차트, OpenDART, 정형 메모·직접 입력으로 설명한다. 주석 추출·요약은 언어모델 API, 재현 가능한 분석/모델은 pandas·NumPy·scikit-learn을 검토한다. 코드 존재·테스트 통과·실데이터 검증을 별도로 확인한다.

GitHub·Drive·Notion 협업, Render 배포 검토를 따른다. 서버 키 관리·접근 제어·요청 제한·캐시, 실제 의존성/버전·비용·배포·응답시간·보존은 미정이다. N-S08의 별도 검증 화면 구현 여부도 미정이다.
