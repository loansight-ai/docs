노션의 요구/기능/화면·미정/WBS는 총 **181개 행**을 페이지 누락 없이 읽었다. PRD는 현재 v0.0.4 영역만 비교하고 이전 버전 보관 영역을 현재 본문으로 세지 않았다. 팀 메모·댓글·작업 본문·담당·진행률·실제 상태를 이 게시 작업에서 덮어쓰지 않는다.

## 원문 간 차이와 현재 적용

범위·표본 표현이 충돌하면 요구사항의 명시적 10/23 팀 결정(4개 업종 확정·렌탈 제외·15/5 논의 필요)을 우선한다. 원문 DOCX/XLSX는 수정하지 않고 바이트 그대로 보관한다. 버전 숫자를 기획안 v2.0에 맞춰 일괄 변경하지 않으며 각 문서의 독립 버전과 게시 개정일을 구분한다.

- 기획안 원문에 남은 업종 후보/렌탈 추가 수집 문구는 현재 범위가 아니다. 제조·건설·도소매·부동산 임대 4개 확정과 장비/물품 렌탈 제외를 적용본에 표시했다.
- 원문의 기능 검증15/정답지5 목표는 요구사항 기준 논의 필요다. 추출40개사 인용·계정 확보 업종별5이상 계획·모델/실험 표본과 구분했다.
- 현재 연계 WBS는 **v1.1(2026.10.24)**이다. PRD v0.0.4 본문의 “이번 요청에서 WBS를 개정하지 않는다”는 당시 PRD 개정 범위를 설명한 기록이며, 이후 개정된 현재 WBS 상태를 뜻하지 않는다. 문서·원문 게시가 구현·학습·검증 완료를 뜻하지 않는다.
- 요건이 인용한 렌탈 제외 기획안과 첨부 v2.0의 해시가 다르므로 같은 원문으로 합치지 않는다. 제공된 v2.0과 요구사항을 각각 SHA256으로 식별한다.

## 점검 후 문서 상태

기획안·PRD·요구·기능·WBS의 GitHub 초기 양식을 최신 전체 내용으로 채우고 누락 PRD/WBS·문서 색인·원문 파일을 추가했다. 설계·테스트·발표·제출 안내는 같은 범위/ID/기간에 맞췄으나 물리 설계·실행·최종 발표파일·제출 승인을 완료로 표시하지 않았다. 과거 회의록·수행일지는 당시 기록을 보존한다.

## 검증의 한계와 남은 결정

문서 일치·참조·해시는 실제 데이터 수집·API 동작·모델 학습·성능·사용성·화면 구현 완료를 뜻하지 않는다. N-U01~20과 임계값·현직자 확인·표본·수용/보류 기준은 그대로 미정이다. 테스트 12개는 미수행 시나리오 초안이다. 기획안의 11/05 09:00 제출과 실제 과정 마감은 N-U09로 확인한다.

## 검증 방법

- DOCX를 단락·표·중첩 표 순서로 읽고 XLSX의 모든 원문 필드를 추출했다.
- 노션 각 데이터베이스의 전체 행·ID·원문 버전·필드와 PRD 현재 본문을 다시 조회했다.
- 원문 파일 6개를 바이트 그대로 복사하고 SHA256을 대조했다.
- Markdown의 ID·전체 값·상대 링크·미정/검토 상태와 WBS 선행관계를 검증한다. 병합 후 main의 각 파일 바이트를 다시 대조해 게시 결과를 확인한다.
