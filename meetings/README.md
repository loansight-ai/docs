# 회의록

[공통 회의록 양식](../templates/meeting.md)을 복사해 날짜별 기록을 작성합니다.

## 파일명

- 일반 회의: `YYYY-MM-DD-주제.md`
- Slack 일일 요약: `YYYY-MM-DD-slack-summary.md`
- Slack 요약의 날짜는 한국 시간 기준 마감일이며, 실제 수집 시작·종료 시각을 본문에 기록합니다.

## 공통 구성

짧은 기본 정보 → 한눈에 보기 → 결정 사항 → 할 일 → 안건별 논의 → 미결 사항 → 참고 자료 → 접힌 회의 준비·원문·수집 정보 → 수동 검토 메모.

Notion 기본 회의록 템플릿과 같은 항목을 사용합니다. Notion은 데이터베이스의 날짜·회의 요약 속성도 함께 기록하고, GitHub는 Markdown 본문에서 해당 정보를 확인할 수 있게 합니다.
To do의 완료 표시(☐/☑)는 회의 후 확인할 때 갱신하며 상세 작업 상태는 관련 Issue를 기준으로 관리합니다.

## 작성 규칙

- 참여자는 실제 회의 참석자 또는 Slack 대화 참여자를 구분해 적습니다.
- 결정 사항에는 근거를, 할 일에는 담당자·기한·완료 기준을 남깁니다.
- 명시되지 않은 담당자·기한은 미정으로 기록합니다.
- Slack 일일 요약은 새 댓글이 달린 이전 날짜 스레드도 확인하며, 원문 링크를 남깁니다.
- 개발 작업은 [code Issues](https://github.com/fin-ai-lab-2026/code/issues), 문서 작업은 [docs Issues](https://github.com/fin-ai-lab-2026/docs/issues)로 연결합니다.
- 자동 생성 결과는 초안으로 표시하고 수동 검토 메모와 구분합니다.
- Notion과 GitHub에 같은 핵심 내용을 남기고 서로의 문서 링크를 연결합니다.

첨부파일이 있으면 본문·표·관련 이미지까지 읽고 안건별 논의에 요약합니다. 파일명만으로 내용을 추측하지 않으며 같은 내용·개정본을 구분하고 파일별 원문 링크를 남깁니다. 읽지 못한 중요 첨부는 누락 사유와 재시도 상태를 기록합니다.
