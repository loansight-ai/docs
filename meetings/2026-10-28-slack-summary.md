### 4. 주석 공유·수집 한계와 재무 데이터 부호 · 점검 중

- 공유자는 대상 회사의 결산기 자료에서 중복·구버전·범위 밖 파일을 제외했다고 설명했다. 첨부 이미지도 감사보고서 중복 주석·정정 전 버전·대상 밖 임대업 자료 제외 사유를 보여준다. 원본 ZIP 내부를 읽어 검증한 결과는 아니다.
- 빈 주석 227문서·번호 미분리 160문서·연결을 작성하지 않는 회사의 짧은 연결 주석 약 5,200건이라는 보고가 있었다. 첨부정정 공시는 원문 미제공으로 일부 미확보됐다고 한다. 이를 전체 공시 원문이 완전 확보됐다는 주장으로 확대하지 않는다.
- 89.9MB 주석 ZIP은 도구의 10MB 제한으로 2회 실패했다. 공유 안내와 이미지로 확인한 수집 상태만 요약했으며 데이터 행·주석 원문을 전재하지 않았다.
- 유형자산 취득의 양수·음수 표기를 유출 금액으로 통일했다는 답변이 공유됐다. 첨부 설명 자체도 실제 음수 건을 원문과 일일이 대조하지 않았고 환급·상계 등 반대 방향이면 정보가 사라질 수 있다고 명시한다. 부호 정규화가 검증 완료된 것으로 기록하지 않았다.
- PostgreSQL 16 사용이라는 댓글과 연결 설정 화면은 확인했다. 접속 성공·전체 적재·웹 연동은 독립 실행하지 않았으며 연결 상세는 전재하지 않는다.

### 5. 화면 개선·RAG·업무 범위 조정 · 검토 제안

- 화면 개선안은 4업종 밖 검색 결과, 더 긴 보고서 기간, 색·확인 버튼·글자 크기, 상단 워크스페이스와 기업 고정 표시, 라이트/다크, 요약에서 상세 이동, 산식 제공 범위를 제안했다. 메모 초안 삭제도 논의 대상으로 남겼다. DART 조회 기간에 관한 댓글은 공식 API 제약으로 검증하지 않았다.
- 챗봇은 RAG로 구현 가능하다는 논의 결과가 공유됐고 데이터·분석 품질에 따라 답변 성능이 달라진다는 조건을 붙였다. 실제 구현·응답 품질·도입 범위는 미확인이다.
- 오준탁은 미니프로젝트 산출물과의 비교에서 다운로드·챗봇·복수 기업 비교·분기 데이터 등의 차이를 찾고 리포트 생성 방식·시각화 개선·캐릭터를 정리했다고 보고했다. 미첨부 산출물을 읽었거나 모두 채택됐다고 보지 않았다.
- 인터뷰 대상의 담당 업무가 소매형 SOHO로 확인됐다는 보고와 범위 유지·발표에서 인터뷰 사실만 언급한다는 정리가 있었다. 특정 인터뷰를 기업금융 전반의 검증 근거로 일반화하지 않는다.
- 강사는 10/29 집중 작업 후 10/30 오전 구현할 것과 덜어낼 것을 나누고 막힌 구간의 목표 완성도를 조정하자고 권고했다. 팀의 최종 범위 결정은 이후 확인이 필요하다.
- **근거:** [시각화 수정안](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793162011955799) · [RAG 논의](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793174885881309) · [강사 피드백](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793174911524869)

### 6. 당일 진행 보고와 수행일지 · 보고

- 김동혁은 최신 확보 결산기 기준 2,277개사의 회계 범위 분류와 미확정 43개사 사유·수치 점검, 계정 통합·주석 제약 공유를 보고했다. 43개사의 공시·감사보고서 재확인과 위험 신호 검증은 미완료다.
- 김동민은 유형자산 취득 값 점검·재무제표 4종 표준화·DB 설계 진행, 서종원은 기업개황/DART/KSIC 11차 매칭·기업 검색 구현을 보고했다. 코드를 실행해 검증한 결과와 구분한다.
- 최수인은 차트·지표 배치·정보 표시 개선과 단계 판정 근거 설계를 보고했다. 오준탁은 기획 개정·참고 조사·시각화·캐릭터 작업을 보고했다.
- 수행일지의 공유 드라이브 업로드 완료가 보고됐다. 외부 드라이브·연결된 외부 산출물은 자동으로 따라가 읽지 않았다.
- **근거:** [수행일지 스레드](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793174380139989)
