## 💬 안건별 논의

### 1. 재무 패턴 분석과 위험징후 · 연결 검토

- 김동혁은 Isolation Forest 이상탐지와 k-means 군집화를 사용한 ‘재무 패턴 분석’ 초안을 공유했다. 기존 상환위험 예측을 대신하며, 초기 초안은 미리 분석한 결과를 보여주는 구조라고 설명했다. 서종원은 실시간 수집이 아니므로 실시간 모델 갱신은 불필요하다는 의견을 냈다.
- 첨부 기획안 v2.4의 7장은 업종별 선정 지표에 따른 5지표 모델·3지표 참고 모델·수치 분석 보류 경로와 고정 모델 버전을 제안한다. 이상도는 연체 확률이 아니고 군집 번호는 위험 순서가 아니며 모델·지표 조합 간 점수를 합치지 않는다고 명시한다. 이는 문서의 설계·진행 보고이며 모델 파일·예측력의 독립 검증은 아니다.
- 김동혁은 기존 연구 결과 재현·산출물 패키지 정리를 보고했지만, 서비스와 모델 사이 CCC·재고회전율·영업CF 음수 처리 등 정의 차이와 연도별 검증이 남았다고 명시했다.
- 오준탁은 자체 표본 상대 판정과 ECOS 참고 분포 분리, 절대 주의 통일 및 미결 기준 목록 정리를 보고했다. 반면 테스트 개정본은 후속 v0.0.7을 근거로 3년 지속 조건을 ‘경고’에서 ‘주의(절대)’로 바꾸도록 제안한다. 직접 확인한 기획안 v2.4에는 지속 경고 후보·보류 표현이 남아 있어 최종 규칙 버전 확인이 필요하다. 미첨부 보고서 v0.0.7 본문을 읽었다고 주장하지 않는다.
- **원문:** [모델 스레드](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793627094624019), [정의 차이·미완료](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793693727306809), [기준 검토 보고](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793694738775099)

### 2. 기획 개정·OFS와 주석 데이터 · 진행 보고

- 첨부 기획안 v2.4는 기업금융·여신심사 담당자의 재무 시각화, 위험징후·재무 패턴·업종별 주석 요약을 중심으로 정리했다. 제조·도소매·건설을 분석 범위로 두며 임대업 주석 정리 이력과 현재 분석 제외를 구분한다.
- 주석 요약은 건설의 PF·조건부 의무, 제조의 재고·채권·설비/개발비, 도소매의 재고·반품·리스·공급자금융을 우선한다. 원문·단위·당기/전기·제공/수취를 보존하고 검출·공시상 없음·미검출·추출 실패를 구분하는 설계다. 확인률은 공시 관행이며 위험도·예측 성능으로 해석하지 않는다.
- 문서에는 OFS 우선·CFS 전환 가능 문구가 남았으나 서종원은 웹 DB의 OFS 통일·CFS 제거와 15개 시연 기업의 2025년 주석 원문 복구, 업종별 구조화 규칙 추가를 보고했다. 최신 테스트 자료도 OFS 고정으로 문서 수정을 제안해 버전 정합성이 남아 있다.
- 최수인은 기획안 v2.5 갱신을 보고했으나 이번 구간 직접 첨부된 기획안은 v2.4다. v2.5 전체 내용을 확인한 것으로 쓰지 않는다.
- **첨부 근거:** [기획안 v2.4](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793671919269309) 4-1·5-0·5-1·7장, [DB·주석 보고](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793693451482769), [v2.5 보고](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793694414837229)

- 문서 개선은 현재 실기업·운영 버전·OFS 기준으로 기대값 교체, 예측 화면을 패턴 분석으로 갱신, 시험 회차별 집계 및 API 예상값 근거 보완이다. 시트의 옛 PASS만으로 현재 전체 통과를 선언하지 않는다.

### 5. ERD와 웹 DB 설명 · 추정과 확정 구분

- ERD 이미지와 설명서는 배포용 SQLite의 기업·재무·지표, 품질/원문 근거, 주석·감사·사건·본문 영역을 설명한다. PostgreSQL 통합 원본 전체 ERD와 구분하며 선언 FK와 공통 키를 이용한 논리 조회 관계를 나눈다.
- 설명서는 이미지·기존 문서·원본 스키마를 대조한 작성자의 정리이며 **실제 웹 SQLite 스키마와 서버 코드는 미확인**이라고 명시한다. selected·ready·상태값·주석 결과와 원문 연결·패턴/메모 저장 위치와 화면별 조회 테이블은 추정 또는 확인 필요다.
- 김동민은 이를 확정하려면 실제 스키마·웹 DB·기준 코드의 대조가 필요하다고 요청했다. 보고서의 회계 기준 및 주석 데이터 경로 차이도 검토 과제로 남겼다.
- **첨부 근거:** [ERD 이미지](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793704034702989), [설명서](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793712179549629) 개요·화면 연결·유의점, [미확인 범위](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793712267885759)

### 6. 발표·시연·현업 의견 · 준비 요청

- 현직자 인터뷰 공유 내용은 검색 표에서 종목코드·세부분류·시장을 먼저 보여주고 대표/부수 업종과 지속적인 DB 갱신을 고려하자는 의견이다. 인터뷰 요청 사항이며 모두 구현됐다고 단정하지 않는다.
- 업종별 5개씩 총 15개 시연 후보가 제안됐다. 제조는 재고·채권·개발비·공급자금융, 도소매는 재고·반품·리스·부문, 건설은 PF·계약자산·보증·소송 등 근거를 연결하기 쉬운 기업을 선정 이유로 들었다. 실제 공시 일치와 시연 성공은 별도 확인이다.
- 시연 영상은 대본→브라우저 조작·녹화→음성·자막→검수 흐름을 검토했고, 자동 제작이 어려우면 다음 날 직접 녹음하는 대안이 보고됐다. 최종 영상 완성은 미확인이다.
