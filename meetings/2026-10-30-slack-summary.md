## 💬 안건별 논의

### 1. OFS 수집과 데이터 연동 · 작업 방향 공유

- 2023년 이후 OFS를 우선 수집하고 주석으로 결측을 최대한 보완해 분석용으로 공유한 뒤 2015~2022년으로 확대·적재하는 방향이다. 최근 자료와 과거 자료 ZIP이 뒤이어 공유됐다. ZIP 내부 미확인 범위는 아래에 적었다. [수집 방향](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793343046403359)
- 수집 코드 4건의 구조를 확인했다. 최근 OFS 전용 수집, 업종 분류·공시 수집·주석 추출·완전성 점검 기능을 포함한다. 동일 이름 두 파일은 별도 파일 ID로 보존했으며 실행하지 않았다. 구조 이미지는 재무 API와 공시원문 수집을 분리하고 주석 값을 표준화 재무에 보완하는 흐름을 보여준다. [코드·구조](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793345985181449)
- DB 설명 CSV·README는 테이블과 열의 용도·관계를 설명한다. excel.zip의 설명서와 CSV 구조에서는 재무값·위험 사건 후보·조회 범위가 기업 코드로 연결된다. 연결·별도 혼재와 회계 범위 전환, 결측과 0, 계정 정의 및 일부 주석 값의 사용 보류가 연동 확인 사항이다. 사건 후보는 원문 대조 전이므로 확정 사건이나 정상 라벨로 단정하지 않는다. [DB 설명](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793336832553779) · [연동 자료](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793323636919799)
- API 수집과 CSV·DB 적재를 최종 서비스에서 어떻게 결합할지는 추가 확인이 필요하다. 이후 corp_code가 없다는 질문은 있는 것으로 정정됐다. [정정](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793334862935799)

### 2. 업종별 주석 요약·산업평균 · 제안과 자료 공유

- 주석 요약은 업종별로 중요하게 보는 내용을 먼저 보여주도록 제안했다. 첨부 DOCX는 경고 사건 → 업종 핵심 주석 → 공통 담보·보증·소송 → 나머지 순서를 제안한다. 제조·도소매는 운전자본과 자산 질, 건설은 PF·조건부 의무, 부동산임대는 담보·만기·임대수입을 강조한다. [주석 문서](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793327557011419) · 문서 결론·업종별 항목·화면 반영안
- 단어 언급률과 방향을 확인한 확인률은 정의가 다르며, 어느 것도 위험 크기나 연체 예측력을 의미하지 않는다. 드물어도 실제 경고 사건이면 우선 확인하고, 부정 문맥·상투적 표현·제공/수취·거래처 연체를 구분한다. 본문으로 보완하는 분양·점포·공실 등은 본문 근거를 표시한다. 자료 버전 재집계, 부정 판별 검수, 리츠와 일반 임대 분리 여부가 남았다.
- BOK 산업평균 ZIP은 지표 값·근거·업종 매핑·산식·ECOS 대응 정보를 포함한다. 설명서상 원천은 별도재무 업종 합계 비율로 기업 중앙값·연결재무와 다르다. 단위·회전율 산식·상위 업종 대응을 맞춰 참고 비교에 사용해야 한다. 원천 통계 및 설명서의 검증 주장은 독립 검증하지 않았다. 첨부 내부 작성일이 공유일 이후로 적혀 있어 버전 시점도 확인이 필요하다. [자료 공유](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793342236890039) · ZIP README·산식/매핑 CSV

### 3. 웹 베타와 개발 · 진행 보고

- 시각화 중심 참고 베타가 공유됐다. 작성자는 DB 제외, 긴 로딩, 오류와 일부 정보 조회 불가를 명시했다. 기존 구현에 일부 반영하고 베타도 유지해 완성되는 결과를 제출하자는 의견이 있었다. [베타 논의](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793347378751699) · [유지 의견](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793347626715749)
- 서종원은 재무 화면·현금흐름 브리지, CSV 연동과 버전 보존, 한국은행·ECOS 참고 비교 및 산식 보완을 보고했다. 오준탁은 주석·위험징후·확률 보류 화면과 챗봇, 시각화 개선 및 배포 설정을 보고했다. 이는 작성자의 구현 보고이며 실제 서비스 접속·기능·보안 검사를 여기서 수행한 결과가 아니다. [개발 보고](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793347463074329) · [베타 보고](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793347824085359)

### 4. 통합 테스트 · 문서 검토

- 공통 양식과 2조 참고 문서는 시나리오 흐름과 기능별 케이스를 나누는 작성 참고 자료다. 2조 결과를 우리 서비스의 테스트 결과로 집계하지 않는다.
- LoanSight 통합 테스트 파일은 시나리오 12개·케이스 63건을 담고, 요약에 PASS 57·FAIL 1·미실행 3·조건 설명(CLARIFIED) 2, 결함 13건 중 조치 11건을 기록한다. 실제 OpenDART·ECOS 연동과 실제 주석 ZIP 적용은 미실행 항목이다. Windows 실행 명령 문제 및 단계 기준 확인이 남아 있다. 파일명 v0.0.2와 내부 표지 0.1 표기는 다르다. [테스트 파일](https://kb-bridge12.slack.com/archives/C0C8L1KGVN1/p1793346599412769) · 테스트 요약·TS-LS-11/12
- 위 결과는 파일에 기록된 수행 보고다. 테스트를 재실행하거나 모든 사례·가이드의 이미지를 재검증한 것은 아니다. 화면의 경고 기준·메모 기능 등과 기획 문서의 정합성도 확인해야 한다.
